D. Fragmented Healthcare Records
   - Medical history scattered across providers

   - Repeated tests and consultations

E. Communication Gap
   - Limited doctor-patient interaction time
   - No follow-up mechanism post-consultation
   - Patients cannot reach doctors for minor queries
   - Lack of health education resources

IMPACT:

5. DATABASE STRUCTURE
================================================================================

TOTAL TABLES: 7

1. USERS TABLE
   - Stores patient information
   - Fields: id, name, email, phone, age, gender, created_at
   - Primary Key: UUID (linked to Supabase auth)

2. DOCTORS TABLE
   - Stores doctor profiles and credentials
   - Fields: id, auth_id, name, email, phone, specialization, experience,
            qualification, license_number, rating, is_verified, is_active,
            consultation_fee, available_days, available_time_start,
            available_time_end, bio, created_at, updated_at
   - Primary Key: SERIAL (auto-increment)

3. APPOINTMENTS TABLE
   - Stores appointment bookings
   - Fields: id, user_id, doctor_id, doctor_name, specialization, date, time,
            reason, status, notes, prescription, diagnosis, rejected_reason,
            created_at, updated_at
   - Status: Pending/Confirmed/Rejected/Completed

4. MEDICINES TABLE
   - Stores medicine reminders
   - Fields: id, user_id, medicine_name, dosage, time, frequency, active,
            created_at

5. SYMPTOM_CHECKS TABLE
   - Stores symptom analysis history
   - Fields: id, user_id, symptoms[], predicted_disease,
            recommended_specialization, confidence, description,
            precautions[], created_at

6. MEDICAL_REPORTS TABLE
   - Stores doctor-generated reports
   - Fields: id, patient_id, doctor_id, appointment_id, report_type,
            report_title, report_content, report_date, attachments[],
            created_at, updated_at

7. PRESCRIPTIONS TABLE
   - Stores digital prescriptions
   - Fields: id, patient_id, doctor_id, appointment_id, medicines (JSONB),
            instructions, valid_until, created_at

RELATIONSHIPS:
- Users → Appointments (One-to-Many)
- Doctors → Appointments (One-to-Many)
- Users → Medicines (One-to-Many)
- Users → Symptom Checks (One-to-Many)
- Users → Medical Reports (One-to-Many)
- Doctors → Medical Reports (One-to-Many)
- Appointments → Medical Reports (One-to-Many)
- Appointments → Prescriptions (One-to-Many)

SECURITY:
- Row Level Security (RLS) enabled on all tables
- User-specific data access policies
- Doctor-specific appointment access
- Cascade delete for data integrity
